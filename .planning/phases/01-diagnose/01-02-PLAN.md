1. Get total file count and all file names:
```powershell
$allLogs = Get-ChildItem 'C:\FusionLogs' -Recurse -Filter '*.htm' -ErrorAction SilentlyContinue
Write-Host "Total Fusion log files: $($allLogs.Count)"
$allLogs | Select-Object FullName, LastWriteTime, Length | Sort-Object LastWriteTime -Descending | Format-Table -AutoSize
```

2. Find FAILED bind attempts (the most important signal):
```powershell
$failedLogs = $allLogs | Where-Object {
    $content = Get-Content $_.FullName -Raw -ErrorAction SilentlyContinue
    $content -match 'FAILED|Failure|Could not|not found' -and $content -notmatch 'No errors'
}
Write-Host "=== Logs containing FAILED/Failure/not found: $($failedLogs.Count) ==="
foreach ($log in $failedLogs | Select-Object -First 20) {
    Write-Host "--- FILE: $($log.FullName) ---"
    Get-Content $log.FullName | Select-String -Pattern 'FAILED|Failure|Could not|not found|Result:|Where:|Log:|assembly' -CaseSensitive:$false | Select-Object -First 30
    Write-Host ""
}
```

3. Look specifically for CtrlWiz-related logs:
```powershell
$ctrlWizLogs = $allLogs | Where-Object { $_.FullName -like '*CtrlWiz*' -or $_.FullName -like '*ctrlwiz*' }
Write-Host "=== CtrlWiz-specific Fusion logs: $($ctrlWizLogs.Count) ==="
foreach ($log in $ctrlWizLogs) {
    Write-Host "--- $($log.FullName) ---"
    Get-Content $log.FullName -Raw | Select-String -Pattern 'FAILED|Success|Could not|not found|Result:' -CaseSensitive:$false
}
```

4. Look for roamer.exe-originated logs (NW process bind attempts):

$roamerLogs = $allLogs | Where-Object { $_.FullName -like '*roamer*' -or $_.Directory.FullName -like '*roamer*' }

## Root Cause(s)

### Confirmed Root Cause: Missing Ribbon Resource Files

**Root Cause A (CONFIRMED):** `CustomRibbon.xaml` and `CustomRibbon.name` are missing from `Contents/Nw25/`.

- The `[RibbonLayout("CustomRibbon.xaml")]` and `[Strings("CustomRibbon.name")]` attributes on `CmdViewpoint` instruct NW's plugin host to load these as loose files from the DLL directory at startup.
- When absent, NW silently suppresses ribbon registration — no error dialog, no crash, no journal entry.
- **Build root cause:** `CustomRibbon.xaml` is declared as `<Page>` in CtrlWizNW.csproj — it compiles to BAML embedded in the DLL instead of being copied to output. `CustomRibbon.name` is `<None>` with no `CopyToOutputDirectory` — never copied.
- **Fix:** Change `CustomRibbon.xaml` build action from `<Page>` to `<Content CopyToOutputDirectory="Always">` (or use a post-build copy target). Change `CustomRibbon.name` to include `<CopyToOutputDirectory>Always</CopyToOutputDirectory>`. Scope to the `Debug NW25|x64` and `NW25|x64` configurations to avoid affecting NW22 or other builds.
