Replace the existing line:

With the following three items (keep all three inside or adjacent to the same ItemGroup — the simplest approach is to replace the single self-closing None with an expanded None plus two new condition-scoped ItemGroups):

Strategy: Convert the bare None item to reference the file without copy semantics for non-NW25 builds, and add two new conditional ItemGroups for NW25. The cleanest edit is:

1. Leave the existing `<None Include="CustomRibbon\CustomRibbon.name" />` exactly as-is (it does nothing for copy — this is intentional for NW22 and other configs).
2. Add two new ItemGroup blocks (immediately after the None-containing ItemGroup's closing tag, or after the Content ItemGroups added in Task 1) — whichever location keeps the file readable:

```xml
  <ItemGroup Condition="'$(Configuration)|$(Platform)' == 'Debug NW25|x64'">
    <!-- NW25 requires CustomRibbon.name as a loose file alongside the DLL.
         The unconditional None item above is inert (no copy). This item
         copies the file for the Debug NW25 build only. -->
    <None Include="CustomRibbon\CustomRibbon.name">
      <CopyToOutputDirectory>Always</CopyToOutputDirectory>
    </None>
  </ItemGroup>
  <ItemGroup Condition="'$(Configuration)|$(Platform)' == 'NW25|x64'">
    <!-- Same for release NW25 configuration. -->
    <None Include="CustomRibbon\CustomRibbon.name">
      <CopyToOutputDirectory>Always</CopyToOutputDirectory>
    </None>
  </ItemGroup>
```

IMPORTANT: MSBuild handles duplicate Include paths across item groups. An unconditional `<None Include="..."/>` and a conditional `<None Include="..."><CopyToOutputDirectory>Always</CopyToOutputDirectory></None>` with matching paths will result in the file being copied when the condition is true. This is the standard MSBuild pattern and is safe.

Do NOT change the existing bare `<None Include="CustomRibbon\CustomRibbon.name" />` — leave it in place.
