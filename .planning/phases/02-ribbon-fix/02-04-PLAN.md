the AdWindows default namespace, which exists in both NW2022 and NW2025. Rebuild and human-verify

Purpose: `NWRibbonButton` (namespace `Autodesk.Navisworks.Gui.Roamer.AIRLook`) does not exist in
NW2025's `navisworks.gui.roamer.dll`. A reflection probe of the NW2025 DLL returned only

NW2025 and NW2022 AdWindows (same assembly already referenced for all container types), and it
exposes the same `Id`, `Size`, `ShowText`, and `Orientation` properties used by `NWRibbonButton`.

Output: Updated `CustomRibbon.xaml` with RibbonButton elements; rebuilt Debug NW25|x64 artifact

  <action>
Edit `CtrlWizNW/CustomRibbon/CustomRibbon.xaml`. Make exactly two changes:

**Change 1 — Remove the `xmlns:local` declaration (line 11).**

Remove this line entirely from the root `RibbonControl` element:
```
    xmlns:local="clr-namespace:Autodesk.Navisworks.Gui.Roamer.AIRLook;assembly=navisworks.gui.roamer"
```
Rationale: `local:` is only used by `NWRibbonButton`. After replacing those elements, the namespace
declaration becomes unused. Leaving an unused `xmlns:local` referencing an absent type causes some
XAML parsers to pre-resolve it and fail. Remove it entirely.

**Change 2 — Replace all five `<local:NWRibbonButton>` elements with `<RibbonButton>`.**

Replace each of the five button elements using the default AdWindows namespace (no prefix). Preserve
`x:Uid`, `Id`, `Size`, `ShowText`, and `Orientation` values exactly.

Old (lines 23-27):
```xml
<local:NWRibbonButton x:Uid="Button_1" Id="ID_Button_1" Size="Large" ShowText="True" Orientation="Vertical" />
<local:NWRibbonButton x:Uid="Button_2" Id="ID_Button_2" Size="Large" ShowText="True" Orientation="Vertical" />
<local:NWRibbonButton x:Uid="Button_3" Id="ID_Button_3" Size="Large" ShowText="True" Orientation="Vertical"/>
<local:NWRibbonButton x:Uid="Button_4" Id="ID_Button_4" Size="Large" ShowText="True" Orientation="Vertical"/>
<local:NWRibbonButton x:Uid="Button_5" Id="ID_Button_5" Size="Large" ShowText="True" Orientation="Vertical"/>
```

New (default namespace = Autodesk.Windows from AdWindows, which already defines RibbonButton):
